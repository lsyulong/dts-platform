# 标签绑定合同

盘点日期：2026-10-09，Asia/Shanghai。本合同描述 `/support/tags` 当前实现的标签定义与业务对象绑定语义。

## 业务边界

标签是租户内的正式 `tag` 资源，颜色必须是 `#RRGGBB`，适用范围是 `all` 或产品目录中的真实分组 ID。绑定目标必须是同一租户、产品目录中已注册的真实业务资源；标签不能绑定另一个标签。范围不是前端筛选提示：服务端会根据当前目录重新判断目标资源所属分组。

当前实现支持单对象绑定、解绑和读取标签的活动绑定清单。批量导入、标签继承、规则自动打标以及各业务目录按标签筛选仍未实现，不能把资源属性中的历史字符串数组当成正式绑定关系。

## 一致性与权限

读取需要 `support:read`，修改需要 `support:write`，每次服务调用都会重新验证 Sa 会话和当前权限。请求携带标签当前版本；标签定义在用户操作期间变化时以冲突结束，客户端刷新后再提交。

绑定和解绑使用租户内唯一幂等键。相同键和相同语义返回原结果；同一键被另一操作、目标或版本复用时拒绝。活动关系、不可变回执和脱敏资源审计在同一数据库事务中提交，审计失败会回滚前两者。回执保存安全的目标代码、名称与操作结果，不保存任意资源属性。

活动关系通过数据库外键保护标签和目标对象，解绑前不能删除任一端。解绑会删除活动关系并保留不可变回执和审计证据。标签后来收窄适用范围时，已有的范围外关系仍允许解绑，避免形成无法清理的悬挂关系；新绑定继续按最新范围拒绝。SQLite 与 PostgreSQL 使用同一仓储接口和约束；SQLite 用于本地验证，PostgreSQL 用于生产控制面。

## 页面行为

标签详情读取当前真实绑定清单，显示目标名称、类型、代码和绑定时间。绑定操作先按标签范围选择资源类型，再通过租户与权限受控的真实资源选择器选对象。每条活动关系提供直接解绑入口，操作对话框预填准确的目标类型和 ID，并为每次用户操作生成新的幂等键。

## 本轮验证

- SQLite 仓储测试覆盖绑定、列表、重放、解绑、幂等键冲突、版本冲突、跨租户拒绝、外键删除保护、不可变回执及审计失败回滚，共 4 项通过。
- `dts-server` 默认 SQLite 配置与 `postgres,engine-ape` 配置均完成离线编译检查。
- 前端标签绑定面板 3 项交互测试、静态检查和生产构建通过；只读用户不显示解绑操作。

上述验证是模块级源码与本地存储验证；整体 POC 按项目计划在全部模块完成后集中进行。
