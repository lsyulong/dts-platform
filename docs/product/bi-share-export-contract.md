# BI 分享与结果导出实施合同

本文定义本产品新增业务的实施合同。目录和页面对齐已购买原型中的分享、导出入口，不代表恢复了原型源代码或全部原始交互。本文只描述真实持久化分享和既有安全查询结果导出，不声明公开匿名分享、外部邮件投递或整个平台 POC 已完成。

## 分享对象与身份

分享绑定当前租户的真实 `bi_report`、当前已发布报表版本、真实成功 `ProductJob` 与其中的成功节点，以及一个明确的真实接收用户。创建者和接收者不能是同一用户。HTTP 请求不能提供运行结果、数据权限、脱敏证明或服务器生成的分享身份。

分享 ID 是内部登录后使用的资源标识；`?share=<id>` 只是定位已持久化分享的链接。打开链接仍需真实 Sa 会话与当前用户身份，不签发匿名令牌，不向分享以外的用户开放结果，也不会继承创建者的数据权限。

创建和撤销要求当前活跃用户具有精确的 `bi:read`、`bi:write` 权限。接收者必须是同租户活跃真实用户，且具有 `bi:read`。仓储在同一事务中重新核验双方用户、租户、角色权限和实际结果来源；服务在创建前还要求创建者能通过当前数据授权及脱敏策略读取该真实结果。收到分享本身不会给接收者添加任何表或列的授权。

## 持久化与版本边界

专属 `BiShareRepo` 管理创建、参与者列表、参与者详情、受控打开和 CAS 撤销，禁止由通用资源 CRUD 制造分享记录。SQLite 和 PostgreSQL 均有迁移 017 与独立仓储实现。关联通过同租户外键绑定真实报表、任务节点及用户；引用保护阻止物理删除仍被分享引用的结果。

创建只允许报表仍为 published 且版本一致；任务必须真实 succeeded、来源为同一报表和版本、执行器为 `bi_aggregate_v1`、节点 succeeded 且已有实际结果，冻结业务属性必须匹配当前报表定义。queued、失败节点、旧报表版本或请求拼造结果不能创建分享。

到期时间以数据库时钟为准，创建时要求距当前时刻至少 60 秒、最多 30 天。`is_expired` 是真实数据库计算字段，不依赖浏览器时钟。撤销只允许创建者使用当前分享版本，原子增加版本并记录 revoked 状态和撤销时间。撤销、到期、创建者/接收者停用、创建者失去 BI 写权限、接收者失去 BI 读权限、报表撤回或版本变化都会阻止后续打开。

分享创建、关系校验打开和撤销记录真实审计，仅保存租户、分享、操作者、操作和时间；审计不保存数据行、SQL、查询参数或凭据。打开过程中审计关系校验成功不代表数据出口已授权；数据查询审计另由 QueryAuthorizationService 根据真实读取情况记录。

## 结果读取与脱敏

`BiShareService::open` 在真实分享关系检查后，以当前读取者调用 `ProductJobService::get`。后者重新检查活跃身份、当前精确数据授权、真实元数据采集证明、冻结执行 SQL 和当前 MaskingService 输出策略；无权限、授权失效或不可恢复的脱敏策略变化均拒绝发布结果。数据库中的实际运行状态和结果保留，不伪造成运行失败。

接收者必须满足自己的当前数据 grant 和输出策略。保存结果的脱敏 receipt 由服务器签名，避免已有 HMAC 输出再次散列；如果读者的当前策略与历史不可逆脱敏不兼容，不能恢复原值，读取必须明确拒绝并要求重新运行。分享不能绕过这个约束。

打开和分享导出在生成响应后再次检查实际分享关系、版本、到期和身份，缩小撤销或授权变化期间的出口窗口。分享导出继续使用同一读取者的结果导出服务；不会先用创建者身份生成文件再转交接收者。

## JSON 与 CSV 导出

`ResultExportService::export(actor, job_id, ExportRequest)` 只接受真实节点 ID、预期来源版本和 json/csv 格式。数据来源限定为 `bi_report`、`sql_document`、`development_workflow`、`data_api` 的真实成功运行和成功节点。必须获得当前读取者的 Authorized 结果视图。

服务读取当前授权且经过当前策略处理的实际结果，严格校验唯一完整列、完整行键集合以及 `row_count == rows.len()`。编码后再读取一次安全视图并核对输出没有变化。最多 10,000 行、1,000 列和 2 MiB 文件；超限失败，不静默截断、不生成部分成功导出。

JSON 是推荐的完整交换格式。它保留真实 columns、rows、row_count、来源/任务/节点/版本和 complete 标记；数据库小数与大整数的已有字符串表示不转为浮点数。真实 NULL 保持 JSON null。文件不包含 SQL、参数、冻结定义或内部 receipt。

CSV 使用 UTF-8、逗号分隔、CRLF；全部单元格双引号包裹，内部双引号成对转义。标准 CSV 没有内建 NULL 语义，本产品使用明确的额外编码，下载接口应同时提供 `CsvEncoding` 元数据：

1. CSV 解析后，精确 `\N` 单元格表示 NULL。
2. 普通反斜线全部加倍，所以字面量 `\N` 不会与 NULL 混淆。
3. 文本首个有效字符（跳过前导空白、CR/LF/tab）为 `=`、`+`、`-` 或 `@` 时前置一个单引号；前导单引号、控制空白和数值形状的文本同样保护。真正的 JSON 数值负数不是公式，不改为公式文本。
4. 数字表示超过 15 位时也加文本前缀，避免电子表格自动丢失精度。文本小数/大整数保持其原始内容。
5. 解码顺序为标准 CSV 解析、识别精确 NULL token、移除一个保护单引号、还原加倍反斜线，最后依据列声明处理类型。只用普通 CSV 解析器不会自动恢复本产品的 NULL 和文本保护语义。

不支持的控制字符会使 CSV 导出失败，此时可选择 JSON。文件名仅使用受控来源类型与经过 ASCII 字符限制的实际任务 ID，避免路径与响应头注入。

## 接口与验证范围

服务接口包括创建、参与者列表/详情、打开、CAS 撤销和受控导出。页面由 HTTP 桥接读取真实成功运行、真实用户与期限，不产生占位分享令牌或示例结果。

新增定向测试源包括四项导出编码单元测试、四项 SQLite 分享仓储测试、三项使用实际 SQLite 仓储与 Sa 会话的分享服务测试。覆盖精度/NULL/公式保护/超限、跨租户和非参与者拒绝、版本和真实成功节点、DB 时钟到期、撤销 CAS、真实角色变更、当前数据 grant 撤回和结果保留。执行器观察值明确为控制面测试夹具，不能当作真实 SwanLake 或全平台 POC；PostgreSQL 的真实实例测试需另行验证。具体执行结果以对应测试记录为准。
