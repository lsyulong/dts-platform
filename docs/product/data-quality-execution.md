# 数据质量执行与结果口径

质量对象、规则、任务是配置定义。校验结果来自持久化任务节点的实际查询结果，报告由这些结果生成；配置保存和定义校验不等于查询已经执行。

## 执行前提

- 调用人必须有当前租户的质量执行权限，且租户已经绑定受控 SwanLake 分析引擎。
- 质量对象引用真实采集的元数据对象，规则只能使用其中实际存在的字段。
- 执行时同时核验内部元数据目录记录、对象版本、字段快照、来源指纹和数据库/Schema/表定位。普通属性中的 `engine_binding` 不能单独证明可执行。
- 任务入队冻结任务、对象、元数据及规则的 ID、版本和属性。Worker 在租约保护下重新核验快照、权限、采集证明及实际查询结果。
- 现阶段质量任务支持手动执行。非空定时计划会明确拒绝执行，直至接入真实调度器。

## 规则与计数

`not_null` 检查目标列不为空。`unique` 将同组重复值的全部行和空值行计入失败行，计数不是“重复组数”或“除第一行以外的重复行数”。这两种规则的 `conditions` 必须是空数组。

`range` 使用数值字段的上下界条件，支持 `gt/gte/lt/lte`，最多一个上界和一个下界，边界必须有实际可用区间。`expression` 支持结构化条件，或者一个经 AST 白名单及真实字段绑定检查的布尔表达式；不允许子查询、聚合、窗口、外部访问或任意函数。

结构化条件采用以下格式，多个条件按 AND 判断：

```json
[{"column":"amount","operator":"gte","value":0}]
```

支持 `eq/ne/gt/gte/lt/lte/is_null/not_null/in`。NULL 或未知布尔结果不会被算作通过。字段标识符目前限制为字母、数字、下划线，长度不超过 128 字节且不能数字开头；不支持的实际名称或字段类型会明确拒绝编译。

每条规则执行只读聚合查询，实际返回 `checked_rows`、`failed_rows`；失败行数不能大于检查行数。零行结果标记为 `empty_data`，失败比例为 null。实际查询失败的检查没有虚构的行数或比例。

可选 `sample_limit` 为 1 至 1,000,000 的整数，真正进入查询的 LIMIT。其结果标记为 `evaluation_scope=sample`，不能解释为全表通过。取样未承诺随机性，也不用于估计总体错误率。

## 查询和报告

结果分页按执行任务分页，一次最多 100 个任务；每个任务可以含多条规则，因此返回检查记录数可以超过任务数。返回值分别包含 `total_jobs` 和 `jobs_scanned`。

读取成功节点、历史任务和报告时会按当前读者重新授权。服务重新读取持久化任务，用固定编译器核验节点与 SQL，核对当前采集证明，并要求读者具有该表完整字段的有效授权或明确管理权限。读者不必是原执行人；原执行人的权限也不能替代读者自己的权限。缺少授权服务配置时拒绝读取实际计数。

汇总前核验统计窗口内每个具有成功结果的任务，返回前再次检查并记录真实访问审计。任一相关结果已经失去访问权时，整个读取返回拒绝；不会悄悄移除该任务并返回偏低的完整统计。完成任务的幂等重试回包也经过同一读取检查。

报告统计时间区间为开始时间闭区间、截止时间开区间，只将完整成功任务的成功节点计入检查总量。失败运行、未完成运行、空数据和采样检查另行计数。总量单位是 `row_rule_checks`：同一行被多条规则检查时分别计数，不是不同物理行的数量。

监控阈值表示已完成检查的失败比例阈值。报告仍保留真实失败行数；`within_threshold` 只表示未超过监控阈值。无结果、空数据、执行错误、未完成任务或不完整窗口的 `threshold_exceeded` 为 null，不产生虚假的“阈值检查通过”。采样情况下有明确的采样状态。

目前单次报告最多扫描 2,000 个任务。未覆盖全部相关历史时返回 `window_complete=false`、`status=incomplete_window`。该限制不会被隐藏成完整统计。报告是依据真实任务生成的即时响应，尚未实现独立报告快照存储或定时发布。

## 验证范围

模块提供 SQL 编译、实际计数映射、快照防篡改、租户隔离、阈值和空数据边界，以及 SQLite 持久化和通用关系 SQL 语义的测试源码。SQLite 测试验证本地持久化和兼容关系语义，不代替 SwanLake/DuckDB 的整体 POC。当前交付阶段没有运行这些测试，也没有启动服务。
