# Axure 产品改造与交付范围

依据：[原型库存](../research/2026-10-08-axure-inventory.md)。用户已选择以两套原型全部功能为目标，同时扩展 Rust 后端，按模块持续交付。原型中的 114 / 92 个页面对象还包含说明、表单、弹窗与页面变体，需要先归并业务模块，不能按对象数量直接生成同样数量的生产路由。

## 交付顺序和真实能力

| 交付模块 | 原型对应内容 | 当前可复用能力 | 必须补齐的能力 | 验收方式 |

| 公共权限底座 | 用户、角色、权限、租户、组织、菜单模板 | 租户内用户/角色管理、统一角色卡片、服务端精确权限检查与会话撤销 | 组织层级、成员关系、菜单/模板、细粒度授权、事务一致性和审计 | 两租户隔离、权限撤销、父子组织约束、服务端授权测试 |

| 数据安全与隐私 | 权限审批/审计、密级、识别、脱敏、水印 | 系统权限、单查询端点租户绑定、凭据加密 | 表/字段级访问、审批、识别/脱敏引擎、水印算法与证据 | 实际拒绝越权查询；规则正确性、审批撤销与审计 |

每次交付同步更新本表，报告实际接通接口和验证结果。具备真实后端能力的页面开放操作；新增业务模型在接口、授权、存储和错误语义齐备后接入页面。演示数据只进入测试环境。

## 2026-10-08 首轮交付

- 登录认证使用正式 `sa-token-rust` 0.2.0：单实例默认内存、可选共享 Redis；退出撤销真实会话，密码重置及账号停用拒绝旧会话，接口按当前数据库权限授权，日志 WebSocket 定期重新检查。升级与配置详见 [认证决策](../adr/0002-sa-token-authentication.md) 和 [启动说明](../../README.md)。
- 修复任务配置丢失、运行 ID/终态持久化、取消确认和调度协议问题；SwanLake 使用有行数、字节和整体时间限制的 Flight SQL 客户端。数据源凭据通过加密仓储进入各消费者。
- 现有登录、数据源、任务、查询、监控、运维及权限页面统一深色左栏、白色顶栏、浅灰内容区和青绿色操作。数据源/任务使用真实表格，角色使用实际字段卡片；浅色默认与既有深色选择兼容，手机导航和弹窗适配视口。
- 浏览器检查发现并修复账号状态翻译键、无标题空图表卡及零分母统计显示。历史 `success_rate` 字段对应“非失败任务比例”，不称为执行成功率；无任务时不展示百分比，无数据源时不显示“连接正常”。
- Rust 服务器 157 项单元、1 项日志脱敏、88 项接口集成回归通过；全 workspace 生产/测试 Clippy 与格式检查通过。前端 33 文件、367 项测试、TypeScript/Vite 构建、格式检查通过，Oxlint 为 0 错误/0 警告。

真实浏览器验收使用隔离 SQLite 和内存 Sa 会话，检查登录、`/me` 恢复、系统用户/角色、权限弹窗、手机导航及退出后的 401；既有两项任务映射/取消 smoke 使用测试接口。真实 ape-dts 源库到目标库、生产 PostgreSQL、共享 Redis、SwanLake/JiaScheduler/DeerFlow 部署的完整链路仍需对应环境验收。构建保留现有约 1.2 MB 主包提示，后续按使用情况拆包。

本轮没有完成全部 206 个原型页面对象；组织、菜单、建模、治理、资产、数据服务及 BI 按上表继续实现。第一轮视觉来自已恢复的原型缩略图与库存，不宣称完整 Axure 交互或逐像素复刻。

## UI 与架构约束

- 使用数据中台原型的深色左侧导航、白色顶栏、浅灰内容区及青绿色操作体系；权限原型的业务组织沿用，其紫色视觉统一到该体系。
- 原文件当前只恢复了类别、标签、部分交互元数据和原生缩略图。没有完整交互渲染或精确布局证据，后续逐模块核对控件与流程。
- 保留一个 workspace，通过公共权限底座与数据业务模块分工实现；详见 [ADR](../adr/0001-modular-workspace.md)。
- 当前全量同步采用追加语义，要求目标表预先存在；重复执行可能重复写入或遇到唯一键冲突。CDC、幂等提交、崩溃恢复和多控制面协调需要独立验收。
- 单机查询与分布式任务调度分别定义能力；多 worker 调度不能自动解释为单条 SQL 的分布式执行。
