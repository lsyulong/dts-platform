# 查询出口脱敏

脱敏规则和用户组保存为租户配置。只有规则与适用用户组都已发布、用户是真实启用的组成员时才应用策略。保存草稿、预览样本、定义校验不会激活策略。修改组成员会使组回到草稿，需要重新发布；停用规则或用户组由具有当前 `privacy:write` 权限的管理者明确执行。

## 真实绑定与方法

规则引用当前租户真实采集的元数据对象及其中实际存在的字段。发布时服务端重新读取目录证明，冻结元数据版本、真实字段类型和采集指纹；客户端不能提供可信绑定。执行和释放结果前核验这些绑定。字段版本或来源变化后，旧规则拒绝应用，需重新校验发布。

- `redact` 将非 NULL 值替换成 `***`。
- `hash` 使用单独服务器密钥的 HMAC-SHA256，包含租户、元数据对象、字段、类型和值的上下文。相同上下文和值生成相同摘要；不使用普通 JSON 中的盐、密码或密钥。
- `partial` 只支持真实 VARCHAR 字段。`keep_start` 和 `keep_end` 均为 0 至 32 的整数，默认各为 2；按 Unicode 标量值保留前后字符，中间替换为 `***`。原值长度不足以留出至少一个被遮盖字符时全部遮盖。该规则不承诺按用户可见字形簇切分。

NULL 仍为 NULL。已转换字段的结果类型变为 VARCHAR，`is_numeric=false`。存在脱敏字段时清除自动图表建议；BI 图表也必须读取已脱敏结果和真实更新后的字段类型，不把遮盖值当作数值。

多个组引用同一规则会合并适用关系。同一字段存在多个不同适用规则时拒绝查询，要求管理者解决冲突；不会任选其中一个。

## 查询与执行边界

服务从已经授权的、不能由客户端构造的 `AuthorizedQuery` 创建脱敏计划。支持真实单表直接字段投影、明确别名和普通星号。实际结果字段与行结构必须匹配；缺列、重复输出名或行数不一致时拒绝返回。

被脱敏字段用于派生表达式、筛选、分组、排序或 DISTINCT 时，当前实现明确拒绝。数字位置排序/分组也拒绝，以防通过原值排序或组合表达式重建敏感内容。普通字段的合法筛选、排序和分组仍可使用；全部字段授权不会隐式绕过脱敏策略。具有适用策略的管理者执行无法解析来源的复杂 SQL 时也会拒绝。

Worker 在保存节点结果前应用脱敏，API 在返回查询结果前应用脱敏。查询权限和脱敏计划都在执行及释放结果前重新检查；适用规则、组版本或字段绑定变化时拒绝结果。缺少脱敏服务配置的用户数据出口不得执行或释放原始结果。

固定质量编译器的真实 COUNT 结果通过内部质量授权 token 识别，只包含检查/失败行计数，不含敏感行样本。它仍核验任务、元数据证明和完整字段授权；客户端不能传入“可信聚合”标签跳过检查。

## 历史结果与证据

任务保存已脱敏行后，服务端使用独立密钥为完整 QueryResult 生成收据，签名绑定租户、查询哈希、策略指纹、字段、行、行数及图表建议。收据不包含密钥或原敏感样本。

历史读取先重新取得当前读者的查询权限与脱敏计划。完整结果及收据验签通过、且当前策略相同时直接返回已脱敏内容，避免对摘要重复转换。策略变化后不可恢复原值的历史结果明确拒绝并要求重新执行。旧记录没有收据时按原始结果应用当前策略。伪造收据、修改历史行或来自其他租户的收据都会拒绝。

`privacy-hmac.key` 位于服务器 `data_dir`，首次创建使用 32 字节安全随机数，采用独占文件创建，不覆盖已有密钥。Unix 文件要求 0600；Windows 限制为当前运行账户与 SYSTEM 的文件权限。此密钥与 Sa-token 用户认证和数据源加密密钥独立。密钥丢失或替换会使旧收据无法验证，不能静默接受旧结果。

预览只处理调用人主动提供的一个有界样本，并返回转换后的值，不持久化原样本。配置审计由真实仓储事务生成，访问审计保存查询哈希、真实授权及元数据身份和实际结果；策略指纹和完整脱敏结果哈希保存在服务端签名收据中。不复制原样本、查询参数或密钥到审计。

## 验证范围

模块提供直接投影/别名/星号绑定、派生和排序旁路拒绝、参数白名单、NULL、Unicode 部分遮盖、租户 HMAC 上下文、签名完整性，以及 SQLite 真实目录证明/发布/用户角色/撤销和停用的测试源码。服务源编写期间未执行 Cargo、启动平台或进行整体 POC；最终由统一验证过程报告实际运行结果。
