# 两套产品的完整功能交付合同

日期：2026-10-08，Asia/Shanghai。来源为 [原型库存](../research/2026-10-08-axure-inventory.md)、[交付记录](axure-delivery-map.md) 和当前代码。用户要求先完成前后端产品模块，再整体进行 POC；本合同用于明确实现目标，不能当作完成证明。

## 范围与现状

当前明确目录包含 19 个分组、83 个业务叶模块：数据产品 63 个，公共权限 20 个。其中文字、字段和操作按原型已恢复的业务标签归并，创建、编辑、查看、弹窗、导入与发布表单进入所在模块，不另建菜单。206 是两份文件内的画布对象总数，不能当成生产模块数量。

目录事实源为 `web/src/product/platform-catalog.ts` 和 `access-catalog.ts`；字段类型和引用语义为 `catalog-types.ts`。目录覆盖目前已确认的业务范围；完整 sitemap、每个交互条件及服务页部分名称尚未恢复。因此 83 是这次归并后的交付单元数，并非已经证明与原型全部画布一一对应的计数。API 管理、服务目录根据已恢复的 API 消费与应用标签归纳为必要业务流程，后续获得完整页面证据时继续核对命名和流程。

`implementation: existing` 表示已有页面或能力可以复用，不表示其原型功能已经完整。`implementation: new` 表示需要新增工作区及领域能力。`actions` 表达目标动作；目录列出 `publish`、`execute` 或 `approve`，不等于后台已经支持这些动作。通用资源 CRUD、菜单可达、UI 按钮可点击均不能单独满足本合同。

目前已存在的数据源、同步任务、运行、查询、运维、租户、用户与角色 API 可以接入新界面；组织、数仓设计、标准、模型、指标、治理、资产、服务、BI 和通用后台新增域在本合同创建时仍需按域实现。每个域交付记录应分别报告 UI、业务 API、存储与执行状态。

视觉统一使用数据中台：深色左导航、白色顶栏、浅灰内容区和青绿色操作。公共权限沿用第二套产品的实体与流程，使用同一视觉。前端按 `workspaceType` 形成表格、树、编辑器、工作流、审批、监控与资产目录等实际工作区，不能用同一种空表格代表全部模块。业务编辑默认使用结构化控件，JSON 编辑只作为必要的高级入口。

## 通用业务约束

- 平台控制面本地开发、测试用 SQLite；生产通过仓储接口切换 PostgreSQL。DuckDB/SwanLake 是分析与数仓的数据平面，不能将平台元数据存储和分析引擎混为同一个数据库选择。
- 写接口校验租户、精确业务权限、字段类型、关联对象、状态流转和乐观版本；读接口必须在服务端按当前租户过滤。`*_id` 引用与数组引用校验目标种类、目标存在及相同租户，不能只校验 JSON 是合法语法。
- `ProductResource` 基础属性为 `id, tenant_id, kind, code, name, description, parent_id, status, properties, version, created_by, created_at, updated_at, references`。目录字段只定义 `properties`；基础属性不重复塞入 properties。
- `code` 在租户和种类范围内唯一；层级不能成环；被有效业务对象引用的定义不能直接硬删。编辑提交带版本，冲突时返回可处理的错误，不静默覆盖。
- 运行结果、访问/调用/登录/操作日志、统计和质量结果由实际流程产生。其 `properties` 字段描述读取结构，不表示开放人工创建结果的权限。
- 发布采用草稿、校验、发布、停用或撤回的受控状态机，记录版本及审计。物理发布与控制面状态分别记录，失败不能变成“已发布”。审批和分发也需要明确 actor、时间、原因、结果与失败状态。
- 菜单模板、门户和前端按钮隐藏不替代后端权限。用户、组织成员、角色和数据授权都必须使用实际身份关系，不靠显示名称匹配。
- 未配置执行引擎或消息渠道时，保存定义可以成功，执行必须明确失败或不可用；不能写入成功结果或伪造统计。源库连接和第三方渠道凭据不能进入浏览器、可读普通属性、日志或导出。调用方应用凭据只允许在负责人首次签发时单次展示；不能进入查询缓存、普通属性、日志或导出，重放与后续查询仅返回摘要。

## 结构化属性约定

| 属性 | 值结构与业务约束 | 首要界面 |
|---|---|---|
| `columns` | `[{name,data_type,nullable,description}]`；字段名非空且唯一，类型由后端白名单校验；可扩展标准引用、主键及默认值 | 模型字段表格，增删行、类型与空值选择 |
| `enum_values` | `[{value,label,description}]`；value 非空且在字典中唯一 | 枚举/字典行编辑器 |
| `conditions` | `[{column,operator,value}]`；operator 为 `eq/ne/gt/gte/lt/lte/is_null/not_null/in`，空值运算符无 value，in 为值数组 | 规则条件构建器 |
| `definition` | `{nodes:[{id,name,sql,depends_on:[]}]}`；节点 ID 唯一，依赖存在，不允许自依赖或环 | 工作流节点与依赖编辑器 |
| `*_id` | 指向当前租户的指定种类或现有领域实体，`referenceKind` 给出目标；提交时后端重新校验 | 有标签的引用选择器 |
| `*_ids` | 稳定 ID 数组；具体目标种类由领域合同限定，去重并校验每个元素 | 多选实体选择器 |
| `sql`、`expression` | 保存文本不等于可执行；先语法和权限校验，执行带行数、字节与时间界限 | SQL/表达式编辑器与实际执行结果区 |

## 工作台与集成

| 模块 / 路径 | 真实 V1 合同 | 完成依据与依赖 |
|---|---|---|

| 任务管理 `/tasks` | 源/目标、同步模式、映射、计划与运行策略；创建、修改、执行、取消和运行详情 | 真实 Pipeline/Run；源目标核对；Ape 支持范围显式说明 |
| 任务日志 `/integration/logs` | 按任务、run_id、级别与时间查看实际日志；展示断线/无日志状态 | 复用运行日志与有定期重新授权的 WebSocket，不生成示例日志 |
| 任务运维 `/integration/operations` | 状态筛选、失败详情、重试和取消确认；区分定义状态与运行状态 | 复用运行仓储和执行适配；终态可追溯 |

## 数仓、标准与模型

| 模块 / 路径 | 定义管理与校验 | 特殊流程与完成依据 |
|---|---|---|
| 业务分类 `/warehouse/categories` | 分类树、排序、负责人，CRUD 与父级引用保护 | 防环及被引用分类删除约束 |
| 数仓分层 `/warehouse/layers` | 分层名称/代码、表名前缀、用途和排序 | 前缀唯一性与模型命名关联；没有硬编码的示例层级冒充客户配置 |
| 数据域 `/warehouse/domains` | 关联业务分类、负责人，树和检索 | 同租户分类引用与被引用删除保护 |
| 业务过程 `/warehouse/processes` | 关联数据域、事件定义、业务粒度 | 指标/模型引用可追溯，粒度不能为空 |
| 数据集市 `/warehouse/marts` | 关联分类、服务对象和负责人 | 与主题域和应用模型的实际关系 |
| 主题域 `/warehouse/subjects` | 关联集市、业务范围和负责人 | 同租户集市引用和层级约束 |
| 命名标准 `/standards/naming` | 表/字段/指标对象类型、表达式和例子 | 实际命名校验输出具体违规对象；坏表达式拒绝保存 |
| 字段标准 `/standards/fields` | 类型、口径、允许空、单位/枚举引用 | 模型字段引用标准时实际验证一致性 |
| 枚举标准 `/standards/enumerations` | 结构化枚举值、显示含义和说明 | 值唯一；被字段引用时不可破坏性删除 |
| 单位标准 `/standards/units` | 符号、维度、基准换算系数 | 同维度才能换算，系数有效；不默默改变已发布指标口径 |
| 模型设计 `/models/design` | 字段编辑、表名、分层/域、主键；表/视图或 SQL 导入；版本差异 | 校验→生成 DDL→物理发布→保存结果；核对实际表结构；失败与兼容性变更单独处理；回滚需具备可执行方案 |

模型发布依赖支持受控写入的 DuckDB/SwanLake 发布适配。现有只读查询边界不能直接当作 DDL 发布能力，也不能将任意用户 DDL 绕过权限送入共享端点。V1 优先安全的建表与非破坏性变更；破坏性修改必须表达数据影响并单独执行。

## 指标与数据开发

| 模块 / 路径 | 定义管理与校验 | 特殊流程与完成依据 |
|---|---|---|
| 原子指标 `/metrics/atomic` | 业务过程、模型、度量表达式、粒度和单位 | 版本校验、发布、实际计算；结果附数据窗口和版本 |
| 派生指标 `/metrics/derived` | 原子指标、修饰词、周期与维度 | 实际生成约束后的指标计算；引用版本固定或明确升级 |
| 复合指标 `/metrics/composite` | 依赖指标和表达式 | 检查缺失依赖、循环和除零；计算结果可核对 |
| 修饰词 `/metrics/modifiers` | 可复用过滤条件和适用维度 | 结合模型类型验证条件，不执行任意代码 |
| 时间周期 `/metrics/periods` | 单位、长度和时区 | 明确起止与周/月边界；长度正数；时区有效 |
| 数据开发 `/development/workspace` | 目录、SQL 文档、参数、目标模型与修订 | 保存版本、校验、发布与执行；执行保留提交 SQL/参数快照 |
| 周期任务 `/development/periodic` | 节点、依赖、Cron、时区、重试策略 | 校验 DAG→发布调度→触发→逐节点实例；依赖失败、取消和重试语义明确 |
| 实时任务 `/development/realtime` | 源目标、映射、消费位点与恢复策略 | 启停/恢复真实持续消费；位点与提交一致；现有仅全量追加适配不能称已完成 |
| 运维概览 `/development/overview` | 工作流/任务实例、失败与真实资源概览 | 复用已有运维范围，新增域实例接入后才计入 |
| 工作流运维 `/development/workflow-runs` | 工作流实例、节点 DAG、状态、错误和时间线 | 引擎产生 run，支持受控重试/取消；不允许手工插入“成功节点” |
| 任务运维 `/development/task-runs` | SQL/节点任务实例与运行状态、日志和错误 | 与数据集成实例区分来源，同时复用统一运行语义 |
| 临时查询 `/query` | 目录、编辑、运行、结果、格式化、保存与受控导出 | 有界查询和实际列类型；不越过租户、数据授权、脱敏或导出限制 |
| 配置管理 `/development/configuration` | 变量、范围、超时、并发和可追踪修订 | 明确引用/覆盖顺序，运行快照固定配置版本；敏感值走凭据设施 |

SQL、指标与工作流实际执行分别依赖分析引擎与调度适配；单机运行和多 worker 分布式任务调度分开定义，不能将多 worker 解释为分布式 SQL。服务未配置时必须明确不可执行。CDC 实时任务需要专门位点、恢复和幂等提交能力。

## 数据权限、安全与隐私

| 模块 / 路径 | 真实 V1 合同 | 完成依据 |
|---|---|---|
| 我的权限 `/security/my-access` | 本人申请、目的、对象/字段、期限；查看、提交和撤回 | 申请不是立即授权；只能撤回允许的本人状态 |
| 权限审批 `/security/approvals` | 审批人、意见、期限；批准/驳回/撤销 | 真实数据授权生成与撤销；不能审批本人申请或超出本人可授权范围 |
| 权限审计 `/security/access-audit` | 授权变化及实际数据访问的 actor、对象、时间和结果 | 只读事件、导出范围控制；不能人工修改成功/失败证据 |
| 数据密级 `/security/classifications` | 有序等级和处理要求 | 引用完整；规则和对象分类使用同一等级体系 |
| 识别规则 `/security/recognition-rules` | 名称/有界样本匹配方式、表达式、级别与样本上限 | 校验表达式和执行成本；识别证据不记录完整敏感原值 |
| 识别任务 `/security/recognition-tasks` | 规则、对象、取样界限与执行实例 | 实际样本匹配、取消及失败原因；保存脱敏证据摘要 |
| 数据发现 `/security/discovery` | 查看发现、字段、分类建议与依据；确认/驳回 | 分类确认来自有效识别结果并记录复核者 |
| 脱敏规则 `/security/masking-rules` | 对象、字段、遮盖/摘要/部分保留与参数；预览 | 实际查询、API、BI 和导出出口应用规则，不能只预览后原值仍被返回 |
| 用户组 `/security/user-groups` | 当前租户成员维护、组与脱敏适用关系 | 校验实际 User ID；禁用账号不因组授权恢复访问 |
| 水印溯源 `/security/watermark-tracing` | 提交文件摘要和提取标记，验证实际导出来源 | 输出具体验证证据、匹配/不匹配/无法验证状态 |
| 水印设置 `/security/watermark-settings` | 来源列或签名清单策略、范围与模板 | 实际导出植入/附加来源标记并可溯源；V1 不声称抗篡改隐形水印算法已完成 |

数据权限必须进入数据平面：当前“一个查询端点绑定一个租户”只提供租户入口约束，不能替代表/字段级授权。SQL AST、视图或受控查询生成必须有明确可实现的约束；没有相应数据平面能力时，不得标记安全模块完成。

| 应用管理 `/services/applications` | 应用负责人、允许来源和凭据期限 | 签发凭据只在创建时返回，仓储存摘要；撤销/到期即时拒绝 |
| 人员 BI 分析 `/bi/personnel` | 查询/模型、维度、度量、图表和版本 | 真实聚合、保存、发布/共享、授权导出；无人员数据不塞示例员工 |
| 标签管理 `/support/tags` | 标签范围、颜色与对象绑定 | 实际对象引用和租户保护；删除处理绑定引用 |
| 告警设置 `/support/alerts` | 运行/质量/健康事件、阈值、接收人、模板与冷却 | 真实事件评估→消息→实际投递结果；测试投递也记录结果 |

## 公共权限与系统

| 模块 / 路径 | 真实 V1 合同 | 完成依据 |
|---|---|---|
| 个人中心 `/account/profile` | 本人资料、修改密码和撤销会话；登录/账号入口延续 Sa-Token | 写实际 User 资料，不创建第二个孤立账号；改密校验旧密码/身份并使旧会话失效 |
| 待办事项 `/account/work-items` | 真实审批/工作流派生待办；领取、处理和截止时间 | 处理必须调用关联业务，不把点“完成”当成审批已批准 |
| 系统统计 `/system/statistics` | 账户、实体与运行的实际周期统计 | 当前租户过滤；按源记录复算一致；禁止人工编辑结果 |
| 使用统计 `/system/usage` | 登录、操作、查询和 API 调用的真实时间/维度统计 | 来源事件可追溯；未采集统计为空而非默认活跃量 |
| 租户管理 `/system/tenants` | 编码、名称、管理员、状态、有效期和模板关系 | 扩展当前只管理本租户范围；跨租户创建/管理必须专门平台权限；停用和到期进入认证拒绝逻辑 |
| 菜单模板 `/system/menu-templates` | 模板、稳定菜单 ID 和版本；分配给租户 | 模板分配影响导航/可用模块，不能授予未有后端权限 |
| 组织管理 `/system/organizations` | 组织树、排序、负责人和成员 | 同租户 User 引用，防环、迁移/删除约束；成员关系持久化 |
| 用户管理 `/system/users` | 账号、资料、组织/组、角色、状态与密码重置 | 延续现有角色校验和会话撤销；新增关系要真实绑定，不靠名称推断 |
| 角色管理 `/system/roles` | 预置/自定义、成员和权限；状态启停 | 不可更改系统角色；不得授予超出自身权限或接管高权限成员 |
| 权限列表 `/system/permissions` | 当前实际注册权限、所属模块与角色绑定 | 权限 ID 必须存在于后台，展示文字不新造有效权限 |
| 菜单管理 `/system/menus` | 受控产品路由、层级、可见、排序与权限 | 校验合法路由、防环；不能允许任意脚本或外部地址执行 |
| 字典管理 `/system/dictionaries` | 字典定义和结构化值；检索/编辑 | code/value 唯一，保护引用与停用行为 |
| 公告管理 `/system/announcements` | 内容、接收范围、计划、有效期；发布/撤回 | 实际收件可见性、过期与撤回规则；安全渲染内容 |
| 登录日志 `/system/logs/login` | 认证产生的真实成功、失败、来源与原因 | 不保存密码/令牌；失败事件租户和隐私范围受控 |
| 操作日志 `/system/logs/operations` | 写 API 自动产生的 actor、资源、动作与差异 | 与写操作保持事务一致；禁止浏览器伪造事件 |
| 系统监控 `/system/monitoring` | 服务、引擎和控制面实际健康指标 | 可复用现有 ops；未启动服务显示未配置/不可用 |
| 消息管理 `/system/messages` | 站内、邮件、短信、企微、钉钉、webhook 的收发、已读和重试 | 站内消息真实成员收件；外发需可用渠道适配与凭据；未发送不能标已投递 |
| 消息模板 `/system/message-templates` | 标题、正文、渠道和变量定义；预览/校验 | 必填变量检查，安全模板替换；预览不等于投递成功 |
| 基础设置 `/system/settings` | 品牌、登录、密码及通知策略；校验后应用 | 登录/密码策略真正被认证及改密入口使用；配置不返回秘密 |
| 门户设计 `/system/portals` | 受控组件布局、主题、角色授权；预览/发布/撤回 | 不运行任意 HTML/脚本；角色引用真实，门户中每个组件仍校验业务权限 |

个人/企业实名、办理人认证、组织认证、支付宝和对公打款等标签在原型中出现，但尚未恢复其独立画布关系和完整流程。它们需要后续归入个人中心/组织的认证扩展合同，核对真实第三方服务、材料、审批、状态、失败及隐私要求；不能仅凭标签写出可用身份认证或支付能力，也不能在未核对前宣称两套产品逐流程已完整实现。注册和找回密码同样需要租户策略、验证渠道、一次性凭据与会话撤销流程，当前登录可用不等于已完成这些入口。

## 分层交付与最终 POC

1. 完成目录中的导航、专属工作区、结构化编辑、筛选、详情、流程状态和反馈；使所有模块入口可审查，明确真实 API 与尚待实现动作。

3. 接通引擎、调度、采集、数据安全、质量、API 与消息适配；实际结果由执行器产生。同步更新本合同的实现记录，不用通用 CRUD 覆盖领域验收。
