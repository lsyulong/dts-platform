# 周期定义与调度适配边界

日期：2026-10-09。本合同记录实际定义校验、计划控制面及社区适配边界。真实 JiaScheduler、PostgreSQL 与 DuckDB 的整体 POC 仍留到功能链路完成后进行。

## 定义校验

新增及编辑周期工作流必须经过产品字段校验和调度语义校验。校验、发布、运行准备及已领取快照重验使用相同规则：

- Cron 为五字段（分、时、日、月、星期），或六字段（最前增加秒）。不接受第七个年份字段。
- 秒/分为 0..59，小时为 0..23，日为 1..31，月为 1..12，星期为 0..7，0/7 均表示周日。支持正向范围、列表、正整数步长、月份及星期英文缩写；日期或星期单独使用 `?` 会规范化成 `*`。
- 拒绝零步长、超出字段容量的步长、反向范围、空列表成员、未知英文值及扩展 Quartz 操作符。此合同校验字段语义，不提供完整日历未来发生时间证明，也未实现“下一次运行”预览。
- 时区必须为有效 IANA 名称，例如 `UTC`、`Asia/Shanghai`。重试次数为 0..10 的整数，缺省为 0。仅有 Cron、时区或重试次数的一部分时拒绝；历史手动 DAG 可以完全省略周期定义。

保存草稿不执行节点、不注册外部调度。发布仍是经过校验的只读定义发布。`DefinitionValidation.schedule_registered` 保持 `false`，`schedule_definition` 返回规范化后的 Cron、真实时区、重试定义及当前适配能力；`automatic_retry_enabled` 保持 `false`。现有运行实例的人工重试与周期自动重试分别表达。

## JiaScheduler 协议与时区

本地社区源码 `D:/rustpro/jiascheduler/automate/src/scheduler/scheduler.rs` 的定时器创建逻辑仅将字面值 `utc` 交给 UTC 分支；其他时区值均交给 worker `Local`。因此当前平台适配器只允许实际 `utc` 定时器提交，不能把任意 IANA 名称当成已经被远端正确消费的时区。

周期定义可以保存有效 IANA 名称；只有 `UTC` 的 `scheduler_timezone_supported` 为真。这个字段只表示时区兼容性。注册动作会再次拒绝非 UTC 定义。同步任务现有调度接口继续使用 UTC。修复任意 IANA 时区支持需要在社区独立开发分支中实现并验证，当前未修改社区仓库。

当前 JiaScheduler worker 依赖的 Croner 使用 POSIX 星期语义，1 表示星期一；见 [Croner 官方说明](https://github.com/Hexagon/croner-rust#why-croner-instead-of-cron-or-saffron)。平台规范化英文名称时使用同一语义。

客户端在保存定时器、派发及修改运行计划前再次校验 Cron 与 UTC 限制；高层 `TaskSync.upsert_job` 在保存作业前先拒绝无效 Cron。无效定义不能通过 HTTP 200 被当成业务成功。现有停止/删除与失败传播测试继续保留。

## 界面及验证

统一绿色编辑器展示字段顺序、星期与步长语义，时区和自动重试的当前状态；重试数输入使用整数及范围约束，服务端再次校验。现有非 UTC 定义保留其实际内容，不静默改成 UTC。工作流画布展示实际计划状态、计划版本、冻结来源版本、Cron、时区和远端待核对错误；注册与停用按钮按计划状态显示。

专项协议测试覆盖无效定义零远端写入；真实 SQLite 服务测试覆盖无效周期策略不改变来源的版本/状态、不发布、不执行查询。通过结果记录在实施台账。生产 PostgreSQL 运行、真实远端定时器及浏览器视觉尚未整体 POC。

## 已接控制面

`development_workflow` 使用独立的内部 `development_schedule` 资源保存计划，不把远端结果写回用户定义，也不因注册改变工作流版本。计划保存来源版本、单调计划版本、规范化 Cron、时区、授权用户、变更原因、幂等键、远端 EID、最后错误和变更时间。SQLite 与 PostgreSQL 复用同一产品资源仓储、CAS 与安全摘要审计。

注册先写 `registering`，再调用 JiaScheduler；确认成功进入 `active`，调用链发生错误则进入 `registration_unknown`，不会伪报成功。停用先写 `stopping`，确认删除远端 timer 后进入 `stopped`，错误进入 `stop_unknown`。相同操作和幂等键只回放已保存结果；变更中的计划拒绝并发操作。远端对象名使用租户与工作流的 SHA-256 截断标识，避免跨租户或与同步任务名称冲突。工作流在计划未确认停用时不能撤回。

回调授权 HMAC 同时绑定租户、工作流、授权用户和计划版本。每次触发重新读取实际启用计划，验证授权用户、租户、Sa 身份与 `development:execute` 权限，再用冻结来源版本进入 ProductJob；来源被修改、撤回或运行配置失效时关闭失败，不替换成新版本。

## 尚需完成的执行链

JiaScheduler 社区执行器当前会生成内部 `run_id`，但不会把它注入 shell 环境。平台因此拒绝 `retry_limit > 0` 的远端注册，并以计划版本和 UTC 秒生成 ProductJob 幂等键；同秒重复回调可重放，跨秒重复仍需真实协议扩展解决。下一阶段应向上游贡献稳定 occurrence/run 标识注入，再实现自动重试、下一次发生时间、专用人工核对/恢复页、多控制面协调和告警。当前可用新幂等键重复注册或停用以执行确定性 upsert/remove，但这不代替真实远端 POC。
