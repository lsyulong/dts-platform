# 本人资料、密码变更与运行日志实施合同

日期：2026-10-08，Asia/Shanghai。本文记录本产品的接口、领域约束和实现边界，不声称恢复了购买原型的内部数据结构。个人中心与集成日志使用专属界面和业务接口；通用资源记录保存不能替代下列功能。

## 本人资料

`PATCH /api/v1/auth/profile` 接受 `{email,display_name}`，成功返回真实 `UserInfo`。用户名、用户 ID、租户、角色与权限由当前 Sa-Token 会话确定，不接受客户端覆盖这些字段，不要求 `user:manage`。

邮箱和名称去除两端空格。邮箱最多 254 字节，必须具有非空的本地部分和域部分，不能包含空白、控制字符或额外的 `@`；允许已有本地账户使用的 `admin@default` 格式。显示名称为 1–120 个字符，不允许控制字符。SQLite/PostgreSQL 更新在同一条 SQL 中限定用户 ID、租户 ID、用户 active 状态和租户 active 状态；唯一邮箱冲突返回业务错误。接口重新读取实际资料、租户名称和当前数据库授权，不返回密码或密码哈希。

前端响应只有与请求发起时的会话一致才可更新登录用户状态和 localStorage。会话切换后的旧响应不得覆盖另一用户的资料。

## 本人密码变更

`POST /api/v1/auth/change-password` 接受 `{current_password,new_password}`，成功返回无正文的 204。请求只操作当前身份；未知请求字段会被拒绝。新密码长度为 12–1024 个 UTF-8 字节，与当前密码不同。后端在阻塞任务中校验当前 Argon2 哈希并为新密码生成随机盐；请求 Debug 输出不含密码。

当前密码错误返回 400，不能作为会话过期的 401，也不能撤销任何会话。真正无效或过期的 Sa-Token 返回 401，继续使用平台统一退出逻辑。

数据库使用 `user_id + tenant_id + active 用户/租户 + expected_password_hash` 比较更新，防止同时改密或管理员重置造成旧请求覆盖新密码。失败的比较更新返回 400，不执行会话撤销。

成功提交数据库之前快照当前用户的 Sa 会话；提交后逐个撤销这些会话，其他用户的会话保持有效。快照和提交之间创建的旧凭证会话也会因为认证时的密码指纹检查而失效；新密码提交后新创建的登录会话不属于旧会话快照。前端收到 204 时只清理该请求对应的原会话，不清理期间另行登录的用户。

数据库提交与 Sa 会话存储属于两个存储系统，不能构成同一数据库事务。若 Sa 清理失败，后端尝试所有快照会话后返回 500 并记录清理失败，密码不会回滚；旧凭证指纹已失效，认证不能重新接受这些旧会话。此情形不能称作全部存储清理成功，也不能把失败响应解释为密码未发生变更。

## 持久化运行日志

`GET /api/v1/tasks/{task_id}/runs/{run_id}/logs?offset=0&limit=200` 要求 `task:read`，返回：

```json
{
  "data": [
    {"id":"实际日志 ID","sequence":1,"timestamp":"2026-10-08T00:00:00Z","level":"INFO","component":"scheduler","message":"运行实例已建立"}
  ],
  "total": 1
}
```

以上 JSON 仅说明响应结构，接口只返回已经持久化的记录。`offset` 不得为负，`limit` 为 1–200 的整数；按单次运行的 sequence 升序分页。total 与该页数据读取同一数据库快照。缺失、其他任务所属或其他租户所属的运行均返回 404；合法但尚无日志的运行返回空数组和 0。前端日志级别筛选只针对当前页，不改变 total 的含义。

日志持久化通过 `TaskLogRepo`，SQLite 使用单条写入语句分配运行内顺序，PostgreSQL 使用运行行锁和事务。复合外键确保 `tenant/task/run` 关联真实且一致，运行内序号唯一；删除对应运行或任务时级联删除日志。日志级别只允许 TRACE、DEBUG、INFO、WARN、ERROR、FATAL，组件名称最多 64 字节，消息最多 8192 字节。

生产 `WsHub` 必须使用 `with_log_service(TaskLogService)`。`push_run_log` 先提交记录，再广播包含实际日志 ID 和 sequence 的消息；存储失败不广播未持久化的成功日志。调度器持久化以下实际观察：运行记录已经建立、引擎已经接受提交、取消请求已经被引擎接受、实际引擎进度/终态、调度失败。日志存储故障记录到受控服务日志，不因此重跑数据管道或捏造日志内容。

引擎诊断采用默认保护规则，仅允许经过审查的固定状态、数字计数和退出代码原文进入数据库/业务 WebSocket。未知诊断替换为明确的保护提示；`task_run.error_message` 同样保护，避免从任务详情绕过限制。将来新增适配器消息需要扩展安全规则并验证不包含连接字符串、凭据或会话标识。

当前 ape-dts 适配器会读取 stdout 中可识别的全局计数，并排空 stderr；它没有把全部原始 stdout/stderr 作为业务日志持久化。日志页面展示上述平台生命周期和进度摘要，不能声称是完整进程输出，不能从 `error_message` 构造完整日志。暂无自动日志保留期限/压缩策略；生产容量策略仍需结合真实运行量确定。

新增 Rust 定向测试源码覆盖 SQLite 运行内顺序、分页与总数、仓储重新构造后读取、租户/任务/运行三者隔离、复合外键、UTF-8 大小限制、删除级联、本人资料边界和并发密码比较更新。Actix 测试源码覆盖无管理权限本人操作、身份字段注入拒绝、错误旧密保留会话、成功改密撤销本人会话、WebSocket 与 HTTP 使用相同持久化记录、查询授权，以及调度器实际观察事件经过日志服务入库。WebSocket 单元测试另验证仓储失败或缺少持久化服务时不广播未保存的成功日志。

本轮已用已有 Python SQLite 执行实际迁移和仓储 SQL，验证迁移重放、顺序分页、所有权隔离、UTF-8 消息限制、复合外键/级联与密码 CAS；Rust 源码已单独 rustfmt。未在本子任务运行 Cargo，未启动服务，未执行外部引擎、PostgreSQL 实例或整体 POC。根任务完成注册和已有工具编译后，再更新 Rust 测试的实际执行结果。
