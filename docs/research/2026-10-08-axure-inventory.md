## 解析方式与证据等级

两个文件都不是 ZIP。实际观察到文件头 `ac ef 09 00`，随后是小端长度字段、压缩标志和两个可变长度整数。JSON 部件索引使用 LZ4 block 编码。本次根据 [LZ4 官方 block 规范](https://github.com/lz4/lz4/blob/dev/doc/lz4_Block_format.md) 以 Python 标准库和一个小型字节解码循环读取索引，检查输入范围、输出上限与解码长度。

两文件的索引大小分别为：数据中台压缩 26,210 字节、解压 42,375 字节；权限系统压缩 7,315 字节、解压 11,771 字节。索引解码后是 `root.children` 与 `parts` 的 JSON 树，部件偏移相对于索引结束位置。

索引后的部件具有八字节记录头，后接 payload。读取到的 package / `DesignDocument` 使用 GZip，缩略图是原生 JPEG。GZip 使用 Python `zlib` 读取；文档和画布内部是 Axure 带字符串表与 GUID 表的二进制序列化对象，不能当作普通 XML/JSON。字符串表可读取到类型、模块名称、控件标签、交互类别和页面链接。这里只提取元数据，不执行任何字符串内容。

这些是针对本次两个文件的格式观察，不是对全部 Axure 文件版本的兼容性承诺。读取限制为索引 2 MB、完整元数据部件 8 MB、画布前缀 250 KB；未全量解压图片或所有子面板。一个大部件触及解码上限后，改为只读前缀以检查类别和字符串表。

本报告区分三类证据：

- **已确认**：索引计数、`Axure:Page` / `Axure:Master` 类型、`DesignDocument` 字符串表内容、所提取 JPEG 的实际视觉。
- **可推断的产品意图**：由模块名称、字段及操作文字归纳出的业务实体和用户流程。
- **尚未验证**：完整 sitemap 层级、每个控件精确坐标和颜色、条件分支、默认面板状态、全部跳转目标与脚本、运行后的交互行为。

Axure 官方将交互区分为事件、条件及动作，并提供页面链接、显示/隐藏、动态面板等功能；静态类别名称的存在不能证明交互已经运行通过。[Axure 官方入门](https://docs.axure.com/)、[动态面板文档](https://docs.axure.com/axure-rp/reference/dynamic-panels/)。
