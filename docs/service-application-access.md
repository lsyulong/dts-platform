# 服务应用、订阅与真实调用权限

服务应用凭据与 Sa-token 控制台用户会话是两个不同的身份入口。应用负责人必须是同租户真实启用用户；普通用户管理本人应用，明确的 `services:approve` 权限才允许管理其他用户应用或处理订阅审批。普通 `services:write` 不包含审批权。已有凭据或订阅历史的应用不能转交负责人。

应用凭据使用系统安全随机数生成的 32 字节秘密，格式为 `dts_app_<UUID>.<base64url>`。数据库只存独立 HMAC 校验摘要，密钥文件为数据目录的 `service-credential-hmac.key`，不使用用户会话或脱敏密钥。摘要绑定租户、凭据 ID 和秘密，核验采用恒定时间 HMAC。明文仅首次签发响应返回；相同幂等请求重放只返回签发事实和安全摘要信息，不能重新取回秘密。响应丢失后应撤销原凭据并重新签发，不能从数据库恢复秘密。凭据、回执和调用审计均不保存密钥、SQL 或调用参数。

订阅保存时绑定同租户真实已发布 API 的当前版本，并冻结负责人、申请人和期限。草稿提交后为待审批；批准或驳回需要真实数据库内的精确审批权限，审批人不能是应用负责人或申请人。批准只能缩短申请期限。已发布 API 的版本变化使旧订阅失效，必须重新申请。驳回与撤销允许关闭已过期或 API 已撤回的申请。决定回执持久化，匹配重放在检查已变化的当前状态之前完成；相同键不同决定、理由或原版本返回冲突，失去权限后不能读取原审批回执。

每次外部调用先核验凭据，再在数据库事务内核验租户、用户、应用、凭据有效期、真实批准订阅和当前 API 发布版本。来源白名单仅是附加限制，不是身份认证：有白名单必须匹配完整 HTTP(S) Origin；空白名单只允许未提供 Origin 的服务器调用。来源不接受路径、用户信息、通配符、查询字符串或片段。

额度按 UTC 分钟同时计入两个桶：租户与 API 的总调用额度、租户与凭据及 API 的凭据额度。两个桶使用 API 发布时冻结的限额，事务原子预留，待完成调用也占用额度；失败、取消和未知结果不退还已用额度。多个凭据不能绕过总额度。SQLite 使用写事务，PostgreSQL 使用租户锁和条件更新。额度拒绝先持久化真实拒绝记录，再返回 HTTP 429 和当前数据库时钟到下一分钟的等待秒数。

只有凭据真实核验后才能产生业务拒绝记录，伪造凭据不会生成冒名调用。订阅、来源、应用停用及额度拒绝与正常许可调用合并分页展示。未知或其他租户目标仅记录 ID 的 SHA-256，不能通过审计获知其他租户 API。拒绝事件没有虚构的执行耗时和结果行数。

外部第一版采用同步调用：原子预留产生不可由客户端构造的许可，随后读取并验证 API 真实冻结定义，通过统一查询授权和脱敏出口执行有界只读查询，返回前再次验证字段权限、应用许可和 API 版本。成功完成记录在数据库事务内再次核验许可后才提交。失败、拒绝或取消保存实际结果，重复完成请求保留第一次真实耗时；已经完成的结果不可改写。

服务崩溃或回复失联时，未完成记录保持 `pending`；已知需要核对的情况可标记 `reconciliation_required`。没有引擎完成证据时不能写成成功。撤销阻断后续授权与返回结果，但不能承诺物理中断已发到远端引擎的查询。

测试源码覆盖 SQLite 实际外键和事务、跨租户与负责人范围、搜索和总数一致、审批权限和幂等回放、撤回后驳回、原子额度、拒绝审计提交、凭据撤销和失败记录、秘密首次返回及不持久化。PostgreSQL 实现使用相同合同，真实 PostgreSQL 集成验证在有数据库环境后进行。本文不代表端到端 POC 已执行。
