# 一个 workspace 内维护公共权限底座与数据中台业务

当前由一名开发者维护，尚无客户，需要将两套 Axure 原型逐模块实现。建议继续使用一个 Git 仓库和 Rust workspace，将公共权限底座、数据中台业务、引擎适配和应用装配划为明确边界；初期共用控制面元数据库和一个 HTTP 服务，减少部署、鉴权协议和版本协调成本。DuckDB/SwanLake 查询的业务数据与存放用户、密码哈希和数据源凭据的控制面元数据必须隔离。

权限底座拥有租户、用户、组织、角色、菜单、权限与审计模型及其迁移。数据业务通过公开的身份与授权接口使用它，权限底座不依赖 Pipeline、数据模型或 DuckDB。数据访问授权单独描述表、字段和访问条件，不能用菜单显隐代替服务端数据授权。

引擎适配器通过稳定的执行、查询、进度和取消接口接入 ape-dts、JiaScheduler、SwanLake；三个上游仓库继续独立管理。未来 worker 可以作为 workspace 内另一个二进制独立部署。出现独立权限产品客户、明显不同的发布节奏或独立扩容需求时，再按已有模块边界拆部署服务；无需先拆仓库。

本 ADR 记录推荐边界与后续开发方向，未宣称本轮已经将所有现有身份代码迁移为独立 crate。

两套前端原型对应同一产品的不同模块；页面、菜单或设计文件的数量不作为服务拆分依据。公共权限底座先服务数据中台，达到独立复用需求后才考虑单独产品化。已有 crate 继续按实际职责维护，避免在尚无明确接口时创建空 crate。`ape-dts`、`jiascheduler`、`swanlake` 的社区主分支和下游开发分支仍分别在各自仓库维护。
