# 使用 sa-token-rust 管理登录会话

按照用户指定，认证模块使用正式发布的 `sa-token-rust` 核心和存储组件 0.2.0，替换自签 JWT 路径。令牌采用 `Random64` 不透明随机值，保留前端 `{token, user}` 登录响应及 Bearer / WebSocket subprotocol 传输约定；旧 JWT 升级后需要重新登录。

每个应用建立独立的 `SaTokenManager` 并在 Actix workers 之间共享，避免全局 `StpUtil` 将应用和测试实例状态混在一起。单个控制面默认用官方内存存储，重启后会话失效；多实例共享会话可选择官方 Redis 存储，当前电脑无需安装或启动 Redis。

用户、租户、角色和权限仍由控制面数据库拥有。通过只读 `StpInterface` 动态查询权限，使用精确匹配并关闭授权缓存；框架不能写入另一份权限副本。每次认证核对账号及租户状态，密码重置后校验凭据版本并撤销旧会话。任务日志连接在现有 15 秒心跳重新认证和授权。

JiaScheduler 的任务授权绑定租户、任务和授权用户，作为独立的机器调用入口保留；它使用相同的身份和业务权限检查。共享认证会话不等于已经实现多控制面运行租约或分布式数据同步。

上游参考源码和发布包已经只读核对，接口依据发布提交 [03bbc0a](https://github.com/sa-tokens/sa-token-rust/tree/03bbc0a510e5781ba710c2f3c7d252b62ff2bc65)。正式依赖从 registry 按版本获取，不依赖本机参考目录。模块保留独立边界，后续可按验证过的版本升级。

0.2.0 的会话清理异常路径存在直接记录令牌的上游日志。主程序强制过滤 `sa_token_core` 日志目标，平台侧错误也不输出框架原始错误；升级版本时需重新核对这一限制。
