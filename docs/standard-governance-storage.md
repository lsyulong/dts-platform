# 标准治理持久化合同

本轮存储模块覆盖命名、字段、枚举、单位四种标准的不可变发布修订，模型对修订的显式绑定，模型发布门禁与采集结构核验记录。SQLite 与 PostgreSQL 使用相同的九个仓储方法。迁移为 `022_standard_governance.sql`，不会删除或改写既有产品定义，也不会把已有配置推断为已发布标准。

## 发布与修订

发布仅接受当前草稿的完整属性与版本；规范化定义及所有子修订必须同事务核验。发布后的资源版本作为 `revision_version`，冻结名称、编码、定义、子修订及 SHA-256。创建后定义不可变，修订状态只能由 `active` 转成 `withdrawn`。新草稿不会撤销旧修订；撤回旧修订不会无故更新当前新草稿。字段标准的单位、枚举标识与版本须成对存在，引用真实同租户的活动修订及完整 hash。

模型绑定只允许修改显式标准引用与 `standard_coverage`，不能借绑定修改字段类型或其他模型定义。字段顺序必须与真实模型一致，全部字段覆盖要求每个字段具备字段标准。绑定同时冻结完整模型定义 hash 和所有递归依赖。已发布模型只有显式 `upgrade` 才能退回草稿重新绑定；绑定时模型版本与后续发布状态版本分开计算。

## 物理发布门禁

准备发布核验当前操作人、租户、精确模型权限、模型版本、完整属性、绑定版本/hash 和全部活动标准修订，然后原子占用 `publishing`。没有真实绑定却声明标准引用的模型会被拒绝；未配置标准的普通模型明确为 `not_configured`。

引擎调用由受控模型发布服务执行，仓储不执行 DuckDB SQL。完成时重验原操作人、标准与当前模型，原子保存模型状态、独立物理回执、依赖证据和门禁结果。仅原门禁版本、`publishing` 状态及属性都不变时才更新模型；旧门禁的迟到回执会独立保存为 `unknown/invalidated`，不会覆盖新模型。真实物理执行后权限或标准失效、回执不完整时保存实际证据并标记 `publish_unknown`，不会声称物理执行已回滚。

同一操作人、门禁版本及相同规范化引擎结果可重放已持久化结果；不同结果返回冲突。超过十分钟的陈旧发布通过当前资源版本 CAS 接管，旧门禁变为 `superseded` 并保留迟到结果接收能力。接管或 `publish_unknown` 的新门禁都带 `needs_reconciliation=true`；调用者必须使用只核对现有表的真实引擎入口，不能再次创建物理表。

成功回执的标准证据结构为：

```json
{
  "model_id": "实际模型标识",
  "model_version": 3,
  "receipt": {"physical_binding": {"table_catalog": "实际库", "schema_name": "实际模式", "table_name": "实际表", "table_type": "BASE TABLE"}},
  "standards": {"state": "validated", "binding_version": 1, "binding_hash": "SHA-256", "dependencies": []}
}
```

`model_version` 是发布占用版本，成功终态模型版本再加一。回执字段、顺序、原生类型和主键有效可空性必须与模型一致。失败或不确定的独立回执不会使用 `published` 状态。

## 已采集结构核验

核验仅接受当前已物理发布模型、当前真实绑定与活动依赖、同租户已采集元数据以及内部采集目录证明。内部表定位、字段快照和重新计算的源指纹必须匹配，不能靠普通资源 JSON 伪造采集证明。当前模型须有唯一成功物理回执，并匹配实际库、模式、表及标准冻结证据。

核验快照 hash 包含完整证据且排除自身 hash 字段；结果写入前在同一事务重读并比较。结果范围固定 `collected_schema`，状态为 `conformant/non_conformant`。`data_values_evaluated` 与 `unit_semantics_evaluated` 固定为 false，因此该记录只说明被采集结构与标准之间的差异，不表示内容值、枚举数据值或单位语义已验证。采集之后发生的物理变化需要再次实际采集才能被观察。

## 并发与容量

SQLite 写事务使用 `BEGIN IMMEDIATE`。PostgreSQL 写事务使用可串行化隔离、租户行锁和实际操作人、角色授权、资源、修订及证明的行锁；序列化失败/死锁返回可重试冲突。读分页使用同事务计数与读取，同租户过滤必需。所有历史证据由真实资源、操作人和修订外键约束，不能通过通用删除制造悬空引用。

首轮支持最多 1000 个模型字段绑定与 256 个独立依赖修订（重复引用先去重），递归深度最多八层，证据总量最多 1 MiB；单个资源定义最多 256 KiB，单个修订或核验结果最多 512 KiB。超限明确拒绝，不回退为未配置或截断成看似完整的证据。审计仅记录资源身份、版本和真实动作，普通资源属性与引擎结果不会复制进通用审计。

SQLite 测试源码覆盖不可变修订、旧修订撤回、子引用失败回滚、绑定并发 CAS、真实回执重放、标准撤回、权限失效、陈旧接管与迟到回执、伪造元数据证明和结构核验范围。此文档不表示已运行这些测试或已完成真实引擎 POC；编译与测试由根任务统一执行。
